# 权利要求书

1. 一种基于边缘计算的智能水表数据采集方法，其特征在于，所述方法由部署于供水管网节点处的边缘计算网关执行，包括以下步骤：采集预设周期内各智能水表上报的原始计量数据，所述原始计量数据包括累计流量值、瞬时流量值和水温值；对所述原始计量数据进行本地异常检测，剔除其中的野值并标记疑似漏损数据；对通过异常检测的数据执行本地聚合，得到所述预设周期内的分区用水量统计结果；以及将所述分区用水量统计结果与压缩后的异常标记数据上传至云端服务器，其中所述压缩后的异常标记数据的数据量小于所述原始计量数据的数据量。

2. 根据权利要求1所述的基于边缘计算的智能水表数据采集方法，其特征在于，所述对所述原始计量数据进行本地异常检测，包括：以所述累计流量值的单调不减特性为约束，计算相邻两次上报之间的流量增量；当所述流量增量为负值且其绝对值超过预设阈值时，将本次上报判定为野值。

3. 根据权利要求2所述的基于边缘计算的智能水表数据采集方法，其特征在于，所述标记疑似漏损数据，包括：当所述瞬时流量值在预设的用水低谷时段内持续大于零且持续时间超过设定时长时，将对应的智能水表标识为疑似漏损对象。

4. 根据权利要求1所述的基于边缘计算的智能水表数据采集方法，其特征在于，所述边缘计算网关采用窄带物联网通信模块上传数据，且在每次上传失败后按指数退避的方式重传。

5. 根据权利要求1所述的基于边缘计算的智能水表数据采集方法，其特征在于，所述边缘计算网关包括本地存储单元，用于在通信中断期间缓存所述分区用水量统计结果，并在通信恢复后按时间顺序补传。

6. 一种基于边缘计算的智能水表数据采集装置，其特征在于，包括处理器与存储器，所述存储器存储有计算机程序，所述处理器执行所述计算机程序时实现权利要求1至5中任一项所述的方法。

# 说明书

## 技术领域

本发明涉及供水管网计量与数据处理技术领域，具体涉及一种基于边缘计算的智能水表数据采集方法。

## 背景技术

随着城镇化推进，供水管网中的智能水表数量迅速增长，单个城市的水表保有量常达到数十万只。现有做法通常是由每只水表按固定周期将原始计量数据直接上报至云端服务器，再由云端统一完成存储、清洗与统计。

这种方式存在两个突出问题。其一，数据传输量大。以每只水表每半小时上报一次、每次上报包含累计流量值、瞬时流量值和水温值三项数据计算，十万只水表每天产生的上报记录达到四十八万条，其中绝大部分是重复度极高的正常数据。其二，漏损发现滞后。管网漏损的早期征兆往往体现在瞬时流量值的细微异常上，而云端通常按天完成一次汇总分析，等到发现异常时漏损已经持续较长时间。

已有方案尝试在水表内部增加本地判断逻辑，但受限于水表的成本与功耗约束，其算力与存储能力都十分有限，难以承担相邻水表之间的数据关联分析。

## 发明内容

### 要解决的技术问题

本发明要解决的技术问题是：现有智能水表数据采集方案中，原始计量数据全量上传导致通信开销大，且漏损异常只能在云端按天批量发现、时效性差。

### 技术方案

为解决上述技术问题，本发明提供一种基于边缘计算的智能水表数据采集方法，由部署于供水管网节点处的边缘计算网关执行。该方法包括：采集预设周期内各智能水表上报的原始计量数据，原始计量数据包括累计流量值、瞬时流量值和水温值；对原始计量数据进行本地异常检测，剔除其中的野值并标记疑似漏损数据；对通过异常检测的数据执行本地聚合，得到预设周期内的分区用水量统计结果；以及将分区用水量统计结果与压缩后的异常标记数据上传至云端服务器，其中压缩后的异常标记数据的数据量小于原始计量数据的数据量。

进一步地，本地异常检测以累计流量值的单调不减特性为约束计算相邻两次上报之间的流量增量，当流量增量为负值且绝对值超过预设阈值时，将本次上报判定为野值。

进一步地，当瞬时流量值在预设的用水低谷时段内持续大于零且持续时间超过设定时长时，将对应的智能水表标识为疑似漏损对象。

进一步地，边缘计算网关采用窄带物联网通信模块上传数据，且在每次上传失败后按指数退避的方式重传。

进一步地，边缘计算网关包括本地存储单元，用于在通信中断期间缓存分区用水量统计结果，并在通信恢复后按时间顺序补传。

### 有益效果

本发明的有益效果是：通过将异常检测与数据聚合下沉到边缘计算网关，上传的数据量由原始计量数据的全量下降为聚合统计结果与异常标记，通信开销显著降低；同时，由于异常检测在网关侧按预设周期实时完成，疑似漏损数据可以在当个周期内被标记并上传，漏损发现的时效性由按天提升到按小时。

## 具体实施方式

为使本发明的目的、技术方案和优点更加清楚，下面结合附图和具体实施例对本发明作进一步详细说明。应当理解，此处所描述的具体实施例仅用以解释本发明，并不用于限定本发明。

实施例一

如图1所示，本实施例提供的智能水表数据采集系统包括若干智能水表、若干边缘计算网关以及云端服务器。智能水表安装于用户端，通过窄带物联网通信模块与所属区域的边缘计算网关建立连接。一个边缘计算网关通常覆盖一个小区或一段市政管道，管辖的智能水表数量在一百至两千只之间。

如图2所示，边缘计算网关包括采集模块、异常检测模块、聚合模块、压缩模块、上行通信模块和本地存储单元。采集模块按照预设周期接收各智能水表上报的原始计量数据。本实施例中预设周期取十五分钟，即每十五分钟完成一轮采集与处理。

如图3所示，本实施例的方法包括以下步骤。

步骤S1，采集原始计量数据。采集模块在每个预设周期内接收管辖范围内各智能水表上报的原始计量数据，每条原始计量数据包括该水表的标识、累计流量值、瞬时流量值和水温值。累计流量值为水表自投用以来的累计计量总量，理论上应随时间单调不减。

步骤S2，本地异常检测。异常检测模块对原始计量数据执行两级判断。第一级判断针对累计流量值：计算同一水表相邻两次上报之间的流量增量，若流量增量为负值，说明累计值发生了回退；当回退的绝对值超过预设阈值时，判定本次上报为野值并将其剔除。本实施例中该预设阈值取零点五立方米，以容忍水表在通信重传时产生的少量乱序。第二级判断针对瞬时流量值：若某只水表的瞬时流量值在预设的用水低谷时段内持续大于零，且持续时间超过设定时长，则将该水表的标识加入疑似漏损列表。本实施例中用水低谷时段取凌晨一时至四时，设定时长取三小时。

步骤S3，本地聚合。聚合模块对通过异常检测的数据按分区执行聚合，得到本周期内的分区用水量统计结果。分区用水量统计结果包括分区总用水量、参与聚合的水表数量以及本周期内新增的疑似漏损水表数量。

步骤S4，数据压缩与上传。压缩模块将疑似漏损列表编码为位图形式，位图的每一位对应一只智能水表，以位值表示是否疑似漏损，从而将异常标记数据压缩到原始计量数据量的百分之一以下。上行通信模块通过窄带物联网通信模块将分区用水量统计结果与压缩后的异常标记数据上传至云端服务器。当上传失败时，上行通信模块按指数退避的方式重传，首次重传等待时间为三十秒，其后每次等待时间加倍，上限为十分钟。

步骤S5，断网续传。在通信中断期间，本地存储单元缓存各周期的分区用水量统计结果；通信恢复后，上行通信模块按时间顺序补传缓存的数据。本地存储单元采用环形缓冲区实现，容量为七十二个周期的数据。

实施例二

与实施例一的不同之处在于，本实施例中边缘计算网关进一步接收云端服务器下发的基线用水量曲线，并在聚合模块中计算本周期分区总用水量相对于基线曲线的偏离度。当偏离度超过百分之二十时，边缘计算网关主动提高采样频率，将预设周期由十五分钟缩短为五分钟，以获取更细粒度的数据用于漏损定位。

本领域技术人员应当理解，本发明的保护范围不限于上述具体数值。预设周期、预设阈值、用水低谷时段与设定时长均可以根据实际管网的规模与用水特征进行调整，只要其落入权利要求所限定的范围内即可。

# 摘要

本发明公开一种基于边缘计算的智能水表数据采集方法，涉及供水管网计量与数据处理技术领域。该方法由部署于供水管网节点处的边缘计算网关执行，包括：采集预设周期内各智能水表上报的累计流量值、瞬时流量值和水温值；对原始计量数据进行本地异常检测，依据累计流量值的单调不减特性剔除野值，并依据用水低谷时段的持续流量标记疑似漏损数据；对通过检测的数据执行本地聚合得到分区用水量统计结果；将聚合结果与压缩后的异常标记数据上传至云端。本发明将异常检测与聚合下沉至边缘侧，上传数据量由全量原始数据降为聚合统计结果，漏损发现时效由按天提升至按小时。本发明主要用于城市供水管网的计量数据采集与漏损监测。
