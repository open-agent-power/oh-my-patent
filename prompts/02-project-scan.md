# 02 · 项目扫描

> **状态：已实现。** 工具：`tools/patent.py ingest`（或单文件的
> `tools/docx_to_md.py` / `tools/pptx_to_md.py`）。
> 本文件是**可执行流程**，按它做。

## 什么时候进入这一步

用户说「帮我看看这个项目」「项目在这个目录」「材料我都放在 `xxx/` 了」，
或者交底材料是 `.docx` / `.pptx` 而不是纯文本时。

**前置检查**（只做一次，别每步都查）：

```bash
cd <仓库根>
python -c "import mammoth, markdownify, pptx; print('依赖就绪')"
```

报 `ModuleNotFoundError` 就先装，**并把这件事告诉用户**（他们可能以为这功能开箱可用）：

```bash
pip install -r requirements-ingest.txt
```

如果装不上（离线、权限、公司源不可用），**不要退回「凭文件名猜内容」**——
直接请用户把关键材料另存为 `.md` 或直接粘贴文本。

## 为什么不能跳过这一步

Agent 读得懂 `.md` 和源码，读不懂 `.docx` / `.pptx`。
最典型的失职是：用户把最完整的方案写在了 Word 里，Agent 只扫了代码和 README，
然后基于残缺信息交出专利点——**而且看起来毫无破绽**。
所以本步的产出必须覆盖用户提供的**全部** Office 材料，漏掉哪份都要明说。

## 步骤

### 第 1 步：先看清有什么，再动手转

```bash
ls -la <目录>
find <目录> -maxdepth 3 -type f \( -name "*.docx" -o -name "*.pptx" -o -name "*.doc" -o -name "*.pdf" \) | head -50
```

先看清单有两个目的：判断材料规模（三五份还是上百份），
以及**当场发现读不了的格式**（`.doc` / `.pdf`），避免转到一半才暴露。

### 第 2 步：批量转换

```bash
python tools/patent.py ingest <目录> -o outputs/scan/<案件名>/
```

要点：

- `ingest` 接受目录或任意多个文件，会自动递归。已自动跳过 `.git` /
  `node_modules` / `__pycache__` 和 Office 的 `~$` 锁文件。
- 输出目录按**案件名**分（例如 `outputs/scan/智能水表/`），不要一股脑堆在
  `outputs/scan/` 下——两个项目的材料混在一起，后面回溯时会分不清。
- 同名不同扩展名的源文件（`方案.docx` + `方案.pptx`）会自动消歧成
  `方案.docx.md` / `方案.pptx.md`，不会互相覆盖。
- **退出码 2 表示有文件失败**，不是「全都完了」。看输出里带 ✗ 的行。

想先试一份再批量：

```bash
python tools/docx_to_md.py -i 交底书.docx -o outputs/scan/<案件名>/交底书.md
```

### 第 3 步：**逐条读告警，一条都不能跳过**

这是本流程里最容易糊弄过去、后果也最严重的一步。
告警既打在终端，也写进了每个 `.md` 的**顶部注记**——先读注记，再读正文。

| 告警码 | 含义 | 你必须做的事 |
| --- | --- | --- |
| `FORMULA_APPROXIMATED` | 文档里有内嵌公式，已转成 `⟪公式N: …⟫` 占位 | **向用户索取原式（LaTeX 或截图）**。占位里的式子是退化的：`1/2` 会变成 `12`、上下标会掉层级。**绝对不要凭占位去写权利要求里的公式** |
| `SLIDE_EMPTY` | 某页连标题都没有 | 那一页多半是纯图形（架构图、流程图）或图片。**回头打开原文件看，或问用户**，不要当成「这页没内容」跳过 |
| `SLIDE_TITLE_ONLY` | 某页只有标题、没有正文 | 这类页面在真实评审 PPT 里**几乎都是整页一张图**（架构图/流程图），图上的文字提取不出来。同样要回看原文件 |
| `IMAGE_SKIPPED` | 图片没导出（用了 `--no-images` 或未指定目录） | 正文里只有位置标记。涉及附图的结论需要用户提供图片 |
| `MAMMOTH` | 转换器自身的提示（未识别元素等） | 逐条判断是否影响技术事实。看不懂就告诉用户「这部分可能没转全」 |

另外，`ingest` 会在结尾列出**读不了的文件**（`.doc` / `.ppt` / `.pdf` / `.xls` 等）：

```
另有 3 个文件没有处理（本工具读不了）：
  · 交底书.doc  —— 旧版 Word，请另存为 .docx
  · 专利检索报告.pdf  —— PDF，请先转成 .docx 或文本
```

**这份清单必须原样转达给用户**。它意味着那几份材料的内容你**完全没看到**——
如果其中恰好是核心技术方案，后面所有结论都是错的。

### 第 4 步：读转换结果

用 Read 逐个读 `outputs/scan/<案件名>/` 下的 `.md`。
文件多时优先读体积大、名字含「交底 / 方案 / 设计 / 需求 / 技术」的。

### 第 5 步：产出扫描摘要

写到 `outputs/scan/<案件名>/扫描摘要.md`，用这个结构：

```markdown
# <案件名> 材料扫描摘要

## 材料清单

| 文件 | 类型 | 转换结果 | 关键内容 |
| --- | --- | --- | --- |
| 交底书.docx | 交底书 | ✅ 已转 | 三档水量控制逻辑 |
| 评审.pptx | 汇报 | ✅ 已转（第 4 页为纯图形） | 技术路线、参数表 |
| 旧稿.doc | 交底书 | ❌ 未转 | **内容未知，需用户提供** |

## 技术事实（按来源标注）

> 每条都要能回溯到「哪个文件的哪一节」。

- 采用双阈值滞回控制，避免水表在阈值附近反复启停。（来源：交底书.docx，第 2 节）
- 采样周期 5 s，上报周期 30 min。（来源：评审.pptx 第 3 页参数表）

## ⚠ 丢失与不确定的内容

- **公式**：交底书.docx 含 2 处公式，已转成占位文本，原式待用户提供。
- **图形**：评审.pptx 第 4 页无文本，疑似系统架构图，需回看原文件。
- **未转换**：旧稿.doc 完全未读。

## 可以用作专利点的线索

（此处只列线索，正式挖掘在 03）
```

**摘要不是可选的**：它是 `03` 的输入，也是用户核对「你有没有漏看」的唯一凭据。

## 明确不要做

- **不要凭文件名猜内容。** 「《智能水表技术方案.docx》」不能推出任何技术事实。
- **不要在 `FORMULA_APPROXIMATED` 存在时写带公式的特征。** 先去要原式。
- **不要把 `SLIDE_EMPTY` 当成「这页不重要」。** 恰恰相反，纯图形页往往是架构核心。
- **不要声称「扫描完成」而不提未转换的文件。**
- **不要修改转换出的 `.md`。** 它们是中间产物；要记的结论写进「扫描摘要」。

## 交付

给用户的说明以「**交付后请确认**」收尾：

- 共扫描 N 份材料，覆盖哪些；
- 有哪几份**没有读到**（含原因）；
- 哪几处公式/图形需要他补充原式或说明；
- 扫描摘要的路径。
