# 01 · 立项与输入确认

## 执行门禁

- **入口**：这是任何专利任务的第一站，先读完本文件再动手。
- **先 Read**：用户提供的全部材料（技术想法、交底书、论文、产品文档、已有稿件）。
- **禁止**：在没定下专利类型之前撰写任何正文。类型错了，后面的权利要求与说明书结构全部要重写。
- **禁止**：在没读到输入材料之前就开始写。用户只给了一句话时，也要先问清关键事实，而不是替他编。

## 定下专利类型

三种类型的文书结构差异很大，必须先定下来：

| 类型 | `type:` | 文书构成 | 关键限制 |
| --- | --- | --- | --- |
| 发明专利 | `invention` | 权利要求书 + 说明书 + 摘要 | 可含方法权利要求 |
| 实用新型 | `utility` | 权利要求书 + 说明书 + 摘要 | **必须有附图**；**只能有产品权利要求** |
| 外观设计 | `design` | 简要说明 + 图片 | 无权利要求、无说明书 |

判断依据是**保护对象**：

| 保护对象 | 类型 |
| --- | --- |
| 产品的形状、构造或其结合 | 实用新型 |
| 方法、工艺、材料、配方、算法 | 发明 |
| 产品的外观形状、图案、色彩 | 外观设计 |

用户没有明确时，按上表推断并**说明你的判断依据**——让他有机会纠正。
不确定就不要猜，直接问。

## 定下输入形态

输入可能长成好几种样子，处理方式不同：

| 输入 | 处理 |
| --- | --- |
| 一句话的技术想法 | 信息不足。先问清「解决什么问题、怎么实现的、有什么效果」，再进入 `06` |
| 技术交底书 / 论文 / 产品文档 | 直接消化，进入 `06` |
| 已有一份稿件（.md） | 先跑 `tools/patent.py info` 看解析结果，再决定走 `06` 还是 `07` |
| 已有一份 .docx | **当前版本读不了 docx**（见 `02-project-scan.md`，规划中）。请用户提供文本或 Markdown |

## 输出

这一站的产出只有两件事，都不落盘：

1. 确定 `type:`
2. 列出你手上真实掌握的技术事实与**尚缺的关键信息**

缺关键信息就直接问。**不要用「本领域常规技术手段」这类话把空缺糊过去**——
说明书必须写到「本领域技术人员能够实现」的程度，糊过去的地方正是审查员会指出的地方。
