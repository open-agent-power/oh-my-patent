# 迭代 · 补充材料（merge）

> **状态：未实现（计划 P4）。本文件是待建功能的规格说明，不是可执行流程。**

## 目标

用户看过交底书或申请文件后说「我再补充一点材料」——把新材料**合并**进现有稿件，
而不是重新生成一份让他重新审阅。

## 触发

- 「我又想到一个实施例」
- 「补充一下附图的说明」
- 「这里是实测数据，加进去」

## 与纠错（`correction.md`）的分界

| | 补充材料 | 纠错 |
| --- | --- | --- |
| 用户在做什么 | 加内容 | 改错处 |
| 常见措辞 | 「补充」「再加上」「还有」 | 「这里写错了」「不对，应该是」 |
| 影响范围 | 通常局部 | 可能牵连权利要求与摘要 |

分不清时**直接问用户**，不要猜。猜错的代价是改错地方，用户还得再说一遍。

## 硬约束

1. **另存带时间戳的新文件，不覆盖旧稿。** 旧稿可能是用户已经发出去的版本
2. **追加修订记录**到案件目录的 `修订对话记录.md`，每条含：时间 / 类型 / 说明 / 产出文件名
3. 补充的内容若影响权利要求或摘要，**必须同步更新并重新自检**——
   只改说明书不改权利要求，会留下「权利要求得不到说明书支持」的隐患
4. 合并后重新跑 `07-self-check.md` 的全套自检

## 验收

连续改稿三次，三份旧稿均在，修订记录完整可追溯。
