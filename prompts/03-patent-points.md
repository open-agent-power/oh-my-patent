# 03 · 专利点挖掘与融合

> **状态：未实现（计划 P2）。本文件是待建功能的规格说明，不是可执行流程。**

## 目标

从扫描结果（`02`）里找出**可申请专利的技术点**，并把用户已写好的零散交底材料
**融合**进来（而不是另起炉灶重写一遍，把用户的心血丢掉）。

## 核心难点

一个项目里通常有多个可申请点，它们的价值差别很大：

| 情况 | 处理 |
| --- | --- |
| 只是常规工程实现（用现成库、按文档接线） | **不是专利点**。不要为了凑数硬写 |
| 有取巧的工程细节但无技术贡献 | 通常不足以支撑创造性 |
| 解决了别人解决不了的具体问题 | 候选专利点 |
| 多个点属于同一发明构思 | 合并为一件申请（单一性） |
| 多个点相互独立 | 拆成多件申请，或分案 |

**同一发明构思的判定**是这一站最容易出错的地方：把不相关的点塞进一件申请，
会被要求分案；把该合并的拆开，用户要多花申请费。

## 输出

每个候选点给出：

1. 一句话的技术方案概括
2. 它解决了什么具体问题
3. 与最接近的现有技术的区别在哪
4. 依据的源文件与位置（可回溯）
5. 建议的专利类型与理由

## 纪律

- **不要替用户判断创造性。** 你的产出是「候选点 + 理由」，不是「这个能授权」。
- 挑不出点就如实说挑不出来。**编一个看起来像专利的点，比说「没有」更糟。**
