- **禁止**：把自检报告当成交付物。**自检发现问题就直接改稿**，改完重跑，而不是交一份问题清单给用户。
- **禁止**：把自检清单写进申请文件正文。
- **禁止**：只跑一次 `lint` 就收工。每改一处，重新跑一遍确认。
- **禁止**：为了让 `lint` 通过而删掉合规的内容。检查码是提示，不是标准答案。

## 跑自检

```bash
python tools/patent.py lint 稿件.md          # 人读
python tools/patent.py lint 稿件.md --json   # 结构化，便于在流程里判断
```

## 结果怎么读

| 级别 | 处理方式 |
| --- | --- |
| `ERROR` | **必须修正**。几乎必然导致补正或不予受理。修正后重跑 `lint` |
| `WARNING` | 需要判断。多数应修正；个别是合法写法的提示（如双独权） |
| `INFO` | 提示性信息，转述给用户供其决定 |

**修正后必须重新跑一遍 `lint` 确认**，不要假设改对了。

## 自检的能力边界

自检是**形式检查**。它能判断「有没有写」，不能判断「写得对不对」。

它**不能**替你判断：

- 新颖性、创造性（这需要检索与实质判断）
- 说明书是否真的充分公开——`AI-001` 命中了关键词，不等于公开到位
- 权利要求是否真的得到说明书支持
- 技术方案是否真的能实现

这些必须由人判断。**不要因为 `lint` 全绿就告诉用户「没问题了」。**
