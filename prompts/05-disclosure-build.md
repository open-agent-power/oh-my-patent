# 05 · 技术交底书

> **状态：未实现（计划 P2）。本文件是待建功能的规格说明，不是可执行流程。**

## 目标

把挖掘出的专利点组织成一份**技术交底书**，作为申请文件（`06`）的输入。

## 交底书与申请文件的区别

交底书是**内部材料**，写给代理师看的，可以写得不正式、可以带保留、可以列多个备选方案。
申请文件是**对外法律文件**，每句话都会影响保护范围。两者不能混为一谈：

| | 交底书 | 申请文件 |
| --- | --- | --- |
| 读者 | 代理师 / 自己 | 审查员 / 公众 |
| 形式 | 自由 | 法定格式 |
| 内容 | 可以说「这块还没想清楚」 | 不能有不确定表述 |
| 多方案 | 可以并列 | 需写成有层次的实施例 |

**先交底书、后申请文件**的顺序不能省：交底书阶段允许含糊，正是为了让用户在这里
把事情想清楚，而不是等到写权利要求时才发现有个关键问题没解决。

## 交付要求

1. **双格式**：Markdown（便于修订）+ `.docx`（便于流转）
2. **时间戳命名**：`{案件名}_{YYYYMMDD-HHMMSS}.md` / `.docx`
3. **不覆盖旧稿**：每次生成都是新文件。旧稿是用户的资产，不是垃圾
4. **残留占位符零容忍**：交付前必须扫一遍「待补充」「XXX」

## 脱敏（四类）

交底书常含不宜外传的内容。交付给外部代理师前应做：

| 类型 | 做法 |
| --- | --- |
| 业务信息 | 抽象化。「用于某银行核心系统」→「用于大规模交易场景」 |
| 分类信息 | 用代号。客户名 → `A` / `B` / `C` |
| 数值信息 | 改为区间或规模描述。「日处理 1200 万笔」→「日处理量达一定规模」 |
| 公司/产品名 | 删除，或替换为中性表述 |

## 公式体例

若交底书含公式：

- 维度用**正体下标**：`b_{i,\mathrm{cpu}}`。不要写成 `b^{cpu}`——上标位置易被误读为幂
- **禁止同一字母多处多义**
- 行内与块级公式的 LaTeX 分隔符**全文统一**
- 块级公式尽量单行，便于后续转 OMML（见 D4 结论）

## 验收

拿一个真实项目跑「扫描 → 专利点 → 交底书」全链路，产出的交底书能直接作为 `06` 的输入。
